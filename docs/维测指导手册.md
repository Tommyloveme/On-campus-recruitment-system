# 校招全流程管理系统 — 维测指导手册

> 本系统覆盖校招候选人从**登记、简历筛选、资审、笔试、面试、报批、谈薪、Offer 到入职**的全流程管理。

> 面向系统维护人员与测试人员，涵盖架构、配置、接口、数据库、部署、排障与测试方法。
> 用户操作说明见网页右上角「操作手册」（`static/manual.pdf`，由 `tools/gen_manual.py` 生成）。

## 1. 系统架构

```
浏览器（原生 HTML/CSS/JS，无构建依赖）
   │  HTTP/JSON (Session Cookie 认证)
   ▼
waitress（多线程 WSGI，默认32线程） ── Flask 应用（app.py 入口 + campus/ 包）
   │
   ├── SQLite（data/candidates.db，WAL 模式）
   ├── 简历文件（data/resumes/<候选人id>_<随机>.pdf|.docx）
   └── 配置文件（config/ 目录，JSON 驱动）
```

- **技术栈**：Python 3.9+ / Flask / SQLite（标准库 sqlite3）/ openpyxl（Excel）/ mammoth（docx 转 HTML）/ reportlab（生成手册 PDF）/ waitress（生产 WSGI）。前端 Chart.js 已离线内置（`static/vendor/`）。
- **并发模型**：waitress 多线程 + 每请求独立 SQLite 连接 + WAL 日志模式（读写不互斥）+ busy_timeout 写锁等待，支撑 500+ 并发用户。
- **模块化原则**：后端按 **路由 / 服务 / 数据 / 配置 / 领域引擎** 分层；前端按 **核心 / 流程页 / 图表 / 管理** 分文件；业务字段与阶段规则全部 **JSON 配置驱动**，改配置即可扩展，无需改数据库结构。

## 3. 配置说明

### 3.1 app_config.json（重启生效；ui 部分刷新页面即生效）

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `server.port` | 8000 | 监听端口（环境变量 `PORT` 优先） |
| `server.threads` | 32 | waitress 工作线程数（环境变量 `THREADS` 优先） |
| `server.max_upload_mb` | 16 | 上传文件大小上限 |
| `ui.page_size` | 15 | 候选人列表默认每页条数 |
| `ui.page_size_options` | [15,30,50,100,0] | 每页条数可选项（0=全部） |
| `ui.clip_max_width` | 320 | 表格长内容截断宽度（px） |
| `backup.interval_hours` | 1 | 自动备份间隔（小时） |
| `backup.retention_days` | 3 | 备份保留天数 |
| `logging.level` | INFO | 运行日志级别，输出至 `data/server.log` |
| `security.default_password` | 123456 | 新建用户的默认密码 |
| `resume.allowed_ext` | [.pdf, .docx] | 允许上传的简历格式 |
| `logs.page_size` | 30 | 操作日志每页条数 |
| `interview.slot_minutes` | 45 | 单次面试时长（分钟） |
| `interview.time_step_minutes` | 5 | 可预约时段步长（分钟） |
| `interview.day_start / day_end` | 08:00 / 20:00 | 每日可设时段范围 |

### 3.2 阶段字段配置（刷新页面即生效）

字段定义位于 `config/stages/_common/fields.json`（公共）与各阶段 `config/stages/<stage>/fields.json`。

每个字段支持：`key`（内部名）、`label`（显示名）、`excel_column`（导入/导出表头）、`excel_aliases`（旧表头别名）、`type`（text/date/select）、`options`、`colors`（徽章颜色）、`visible`/`editable`/`importable`/`required`/`multiline`。

- **新增字段**：在对应阶段 `fields.json` 的 `fields` 数组追加一项；Excel 模板、表格列、编辑表单、图表维度自动联动。
- **删除字段**：从 JSON 移除；历史 JSON 数据中该 key 仍保留但不再展示。
- **分组覆盖**：`fields_group_<id>.json` 仅含 `visible` 映射；组管理员在「系统管理」保存时自动生成。

### 3.3 主数据表导入配置

目录：`config/master_import/<页面>/`（当前仅 `registration`）。

| 文件 | 说明 |
| --- | --- |
| `index.json` | 数据源列表、全局导入开关、电话/姓名匹配键、二层部门→分组映射 |
| `stage_rules.json` | 按字段组合判定 `current_stage`；`values` 中 `*` 表示任意非空，亦支持通配符 |
| `sources/*.json` | 各 Excel 数据源列映射；表头支持 `match_patterns`（如 `*手机*`） |

主数据表导入为**全局**匹配（不选分组），不提供模板下载；新建候选人按 Excel「二层部门」列解析分组。

## 4. 数据库

SQLite，6 张业务表（建表语句见 `campus/db/schema.py`）：

| 表 | 关键字段 | 说明 |
| --- | --- | --- |
| `groups` | id, name | 权限分组（二层部门） |
| `users` | username, password_hash, role, group_id | 用户与角色 |
| `candidates` | group_id, data(JSON), resume_file | 候选人；业务字段全部存于 data JSON |
| `logs` | user_name, action, candidate_id, message | 操作审计日志 |
| `interviewer_availability` | user_id, interview_type, avail_date, start/end_time | 面试官可约时段 |
| `interview_bookings` | interviewer_id, candidate_id, start_at | 面试预约记录 |

- **升级兼容**：`init_db()` → `migrate()` 自动补列/建表。
- **自动备份**：启动后立即备份，之后按 `backup.interval_hours` 定时快照至 `data/backups/`；管理员可手动备份/恢复。
- **整机备份**：复制整个 `data/` 目录（建议低峰期；WAL 模式需同时复制 `.db-wal`/`.db-shm` 或先 `PRAGMA wal_checkpoint`）。

## 6. 权限模型

| 操作 | admin | global_viewer | group_admin | editor | viewer |
| --- | :-: | :-: | :-: | :-: | :-: |
| 查看候选人 | 全部 | 全部 | 本组 | 本组 | 本组 |
| 新增/编辑 | 全部 | × | 本组 | 本组 | × |
| 删除候选人/简历 | 全部 | × | 本组 | × | × |
| 全局总览/图表 | 全部 | 全部 | 本组 | × | × |
| 系统管理 | 全部 | × | 本组成员 | × | × |
| 添加用户 | 任意角色 | × | 本组成员/只读 | × | × |
| 字段显示配置 | 各组 | × | 本组 | × | × |

核心校验：`campus/auth/permissions.py` 中 `can_view_group / can_edit_group / can_delete_group`；**安全以后端为准**，前端按钮显隐仅为体验优化。

```bash

chmod +x start.sh && ./start.sh
```

### 7.1 维测脚本（scripts/）

| 脚本 | 说明 |
| --- | --- |
| `status` | 端口监听、PID、app.py 残留进程 |
| `stop` | 优雅停止 |
| `force_stop` | 强杀端口进程 + 所有 app.py python 进程 |
| `restart` | 停止后重启 |
| `manage.py start` | 后台启动，日志追加至 `data/server.log` |

- **运行日志**（`data/server.log`）：INFO 记录关键操作；DEBUG 额外输出查询统计、导入列映射等。
- **升级步骤**：备份 `data/` → 替换代码 → `pip install -r requirements.txt` → 重启（`migrate()` 自动执行）。

## 8. 测试指导

### 8.1 冒烟测试（推荐每次改动后执行）

```bash
python app.py --demo     # 终端1：带演示数据启动
python smoke_test.py     # 终端2：全量冒烟
```

覆盖：登录鉴权、10 阶段配置、CRUD、Excel 导入（含 120 人批量）、主数据表路径、简历上传/预览/打包、四级角色权限、备份恢复、60 并发会话。**全部 PASS 即可发布。**

### 8.2 手工回归要点

1. 左侧导航：候选人登记、校招流程各阶段、Offer 策略、入职管理、数据看板、管理看板。
2. 候选人登记：主数据表导入在「+ 新增候选人」右侧；全局导入、无模板下载。
3. 技术面/主管面：面试官设时段、接口人日历预约。
4. 列筛选 + 全局搜索 + 分页 + 日期排序。
5. 数据图表三种日期粒度；组管理员只见本组。

### 8.3 性能验证

`smoke_test.py` 含 60 并发会话压测，正常数秒内完成。瓶颈通常在登录密码哈希与磁盘 IO。

## 9. 常见故障排查

| 现象 | 排查方向 |
| --- | --- |
| 端口被占用 | `scripts/status.bat` 或 `netstat -ano \| findstr :8000`，清理残留 python |
| 请求 404 但代码有路由 | 多个旧实例同时监听，force_stop 后重启唯一实例 |
| database is locked | 确认 WAL 已启用；检查外部工具长期占用写事务 |
| docx 预览 500 | 文件非真正 docx；提示下载原文件 |
| 修改 fields.json 后异常 | JSON 语法错误；key 重复或改名导致旧数据不显示 |
| 主数据导入全部跳过 | 检查用户对该分组是否有编辑权；Excel 是否含必填「候选人」列 |
| 会话全部失效 | `data/.secret_key` 被删除重建（正常现象） |

## 10. 代码导读（二次开发）

### 10.1 后端扩展路径

| 需求 | 修改位置 |

| 新增流程阶段 | `config/stages.json` + `config/stages/<stage>/fields.json` |

| 阶段判定规则 | `config/master_import/registration/stage_rules.json` |
| 数据库新表/列 | `campus/db/schema.py` 的 `SCHEMA` 与 `migrate()` |
| 新增角色 | `campus/auth/permissions.py` + 前端 `core.js` 权限函数 |

### 10.2 前端扩展路径

| 需求 | 修改位置 |
| --- | --- |
| 新侧边栏入口 | `static/js/main.js` 的 `buildNavStructure()` |
| 新流程阶段页 | 一般无需改代码，`stage-view.js` 按配置渲染 |

| 新图表维度 | 字段 `type: select/date` 自动出现在 charts |

### 10.3 模块依赖关系

```
app.py
  └── campus.create_app()
        ├── campus/db/connection     ← 所有路由
        ├── campus/auth/             ← 装饰器 + 权限
        ├── campus/config_loader     ← 字段配置
        ├── campus/stage_engine      ← 主数据导入 + current_stage
        ├── campus/interview_schedule← 面试日历
        └── campus/routes/*          ← HTTP 入口（薄层，调用 services）
```

**原则**：路由层只做参数校验、权限检查、调用服务、返回 JSON；SQL 与文件 IO 集中在 `services/` 或 `db/`；配置与规则一律 JSON 外置。
